## 무엇을 고쳤는가

검토에서 지적한 실행·관측 문제를 수정했다. C 생성식, 파라미터 초기화,

| 문제 | 수정 |
| --- | --- |
| 모델이 쓰지 않는 DFS·cycle 계획과 origin target을 준비·복사 | `inputs.py`에서 필요한 텐서만 준비. 기존 sampler의 노드·엣지 선택과 보정은 재사용 |

`diffusion.py`는 기존 row 전파의 연산 순서와 sparse propagation 커널을 유지한다.
degree/계수 검사를 위해 반환 경로만 분리했다. clipping이나 새로운 정규화는 없다.
forward는 topology 객체를 요청하지 않는다. 샘플러에 필요한 adjacency와 문맥 정보,
기존 beta에 필요한 그래프 통계는 유지한다.

## 새 관측을 읽는 방법

`features_before_update`는 H/query/key별로 다음을 head마다 기록한다.

- `rms_by_head`: 절대적인 특징 크기.
- `within_context_centered_rms_by_head`: 같은 문맥 안의 노드별 차이.
- `edge_difference_rms_by_head`: 실제 엣지 양 끝의 특징 차이.

`alpha_before_source`는 실제 forward에서 사용한 계수다. optimizer 갱신 전
동일 입력 재실행과 갱신 후 동일 C의 계수 재계산을 별도로 기록한다.
`canonical_cpu_float64_alpha_change`는 실제 생성된 C를 CPU FP64에서 정규화한
기준 차이다. 모델의 계산 정밀도를 바꾸거나 FP32 C에서 사라진 차이를 복원하지 않는다.

`alpha_change_resolved_above_observed_replay_by_head`가 true가 되려면 raw C가
바뀌고, GPU alpha 변화가 측정한 무갱신 재계산 차이보다 크고, FP64 기준 차이도
그 재계산 차이와 64×FP64 epsilon 모두보다 커야 한다. 이 값은 **측정한 수치 오차와의
구별 여부**다. 통계적 유의성·학습 성공·분류 유용성 판정이 아니다.
무갱신 관측 몇 번이 가능한 모든 GPU 합산 오차의 상한을 입증하지도 않는다.
원래 GPU 차이는 숨기거나 0으로 덮지 않고 그대로 남긴다.

AdamW 잔차는 `actual_update - (-lr * weight_decay * parameter_before)`다.
과거 gradient의 optimizer 상태와 반올림도 포함하므로 현재 CE의 순수 기여라고
부르지 않는다. 실제 CE 미분은 `generator_gradients`와 live C gradient에서 확인한다.

판정하지 않는다. weight decay나 초기화·전파를 임의로 바꾸지 않았다.

동일 조합의 fixed 로그에서는 GPU alpha 차이가 최대 5.9605e-8로 남았지만,
CPU FP64 기준 차이는 모든 층에서 0이었다. 모든 head의 변화 판정은 false다.
learned 8층도 C 변화 0이므로 학습에 의한 alpha 변화로 표시되지 않는다.
learned의 3–8층에서는 모든 head가 새 수치 구별 기준을 통과하지 못했다.
1층은 8개 head, 2층은 6개 head가 기준을 통과했다. 이것도 해당 초기 관측에서의
수치 구별 결과이며, 분류에 도움이 되는 가중치를 배웠다는 결론은 아니다.
