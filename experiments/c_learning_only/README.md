# CGAT 연구 v2.0 — C가 배우고 쓰이는지 먼저 확인

## 이번 질문

**여러 부분그래프에서 공유 C 생성기를 학습하면, 이웃의 반영 비중을 배우고
그 차이를 분류에 사용하는가?**

기존 `information_flow_v2`는 여러 보완을 포함한 이전 후보로 보존한다.
이번 실행 경로는 `experiments/c_learning_only`다. 저장소의 과거
`research/conductance_gat/v2`와는 다른 연구 버전이다.

## 무엇이 실행되는가

부분그래프 샘플링 → 입력 변환 → 기존 C 생성 → 이웃 가중 집계 →
기존 출력 변환·ReLU·dropout → 다음 층 → 분류 CE 학습.

- 한 forward의 모든 층은 같은 노드·엣지를 쓴다. 다음 배치에서 다른 문맥을 받는다.
- 기존 비용 계산과 8회 내부 최적화, 그래프 문맥, beta, 초기화는 유지한다.
- 같은 층 q² 보완, 경계 에너지 보완, 층간 교차항, 흐름 저장, 복원·cycle 진단은 없다.
- `information_flow_v2.runner`를 호출하지 않는다. 기본 연산과 데이터 준비만 재사용한다.
- 기본 모델 전체를 CE로 학습한다. C 외 파라미터를 얼리지 않는다.

| 조건 | C | 공통 파라미터 |
| --- | --- | --- |
| learned | 입력에 따라 기존 생성기로 계산하고 생성기를 학습 | 학습 |
| fixed | 모든 엣지·head에서 1, 생성기와 내부 반복 없음 | 학습 |

고정 조건은 같은 초기 모델을 복사한 뒤 생성기를 파라미터 없는 ones 모듈로 교체한다.
공통 파라미터 초기 hash와 매 epoch의 샘플 순서 hash를 비교한다.
초기 C와 예측은 두 조건에서 다를 수 있으므로 초기 validation도 기록한다.

## 무엇을 보면 되는가

매 epoch 첫 학습 배치에서 모든 층·head를 관측한다.
각 층의 입력·엣지·문맥을 고정해 optimizer 갱신 전후의 다음 값을 비교한다.

1. 엣지별 비용 → C → 실제 수신 노드별 반영 비중 alpha.
2. 실제 집계에 쓰인 C의 CE gradient, 생성기 파라미터 gradient와 갱신량.
3. 실행 전에 정한 기준으로 선택한 노드의 모든 이웃에 대한 전후 표.

첫 배치 관측을 전체 학습 데이터의 관측이라고 부르지 않는다.
관측용 계산은 loss를 추가하지 않으며 optimizer를 갱신하지 않는다.
표의 alpha는 이웃 사이의 상대 비중이다. 자기/이웃 혼합 beta는 별도로 유지한다.

## v2.0 결과 판단

| 판단 | 확인할 증거 | 그 자체로 뜻하지 않는 것 |
| --- | --- | --- |
| 배웠는가 | 같은 입력에서 비용·C·alpha가 갱신에 따라 변하고 CE gradient가 도달함 | C 값의 변화만으로 유용성 입증 |
| 사용하는가 | 학습된 모델에서 생성 C만 1로 바꾸면 전달 특징·예측이 달라짐 | 별도 학습한 고정 C보다 우수함 |
| 도움이 되는가 | 동일 조건에서 따로 학습한 고정 C와 validation·새 샘플 문맥 성능 비교 | 한 seed의 차이만으로 보편적 우수성 입증 |

비균일 C를 강제하는 loss는 넣지 않는다. `C 평균=1`은 모든 C가 1이라는 뜻이 아니다.
실행 완료와 연구 성공은 별개다. 결과 파일은 `run_completed`와
`c_benefit_confirmed`를 분리하고 후자는 자동으로 true로 만들지 않는다.

## 버전 진행

- **v2.0:** 위 두 조건의 학습·사용·효과를 확인한다. 원인이 확인된 버그는 같은 범위에서 수정한다.
- **v2.1:** 결과를 검토한 뒤 다음 변경 하나를 정한다. 빠른 로컬 생성기 비교 또는 정보 보완 등이 후보지만, 지금 확정하지 않는다.
- **이후 버전:** 앞선 기준 결과를 보존하고 한 단계씩 추가한다. C가 배우지 않는 상태에 여러 보완을 한꺼번에 얹지 않는다.

**v2.0 통과는 GATv2보다 빠르다는 뜻이 아니다.** 현재 생성기는 그래프 문맥과
반복 최적화를 사용한다. 속도·로컬성·표현력 비교는 조건을 명시한 별도 실험이다.

수식은 `MODEL_MATH.md`, 실행·파일 해석은 `RUN.md`, 실제 검증 범위는
`VERIFICATION.md`를 읽는다. 본학습 결과는 아직 없다.
