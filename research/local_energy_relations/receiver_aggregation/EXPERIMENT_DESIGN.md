# 다음 실험: 수신 측 집계와 실제 복원 가능성

## 확인할 질문

이전 실험은 로컬 v에서 이웃 로컬 u로 보낼 때 공통 노드만 복사하는 범위와, 내부 에너지·쌍선형 관계를 각각 측정했다. 이번에는 **여러 송신 로컬에서 같은 수신 행으로 들어온 값을 실제로 합친다.**

1. 송신 로컬을 구분한 receipt R에서 합 Y로 바꿀 때 어떤 송신별 차이가 직접 보이지 않는가?
2. 현재 실제 메시지 제약 q_v=C_vB_vM_vH 아래에서 그 차이를 전체 Y로 복원할 수 있는가?
3. Y에 실제 내부 이차 에너지 E와 로컬 사이 쌍선형 J를 연결했을 때, 그 항은 Y로 결정되는 값인가?

기본 합이 이미 실제 q를 결정한다는 결과도 유효한 결론이다. 교차항의 이점을 전제로 실험을 설계하지 않는다.

## 고정하는 계약

| 항목 | 범위 |

세 citation 그래프의 원래 row-sum-normalized float32 특징을 float64로 올린 입력을 그대로 쓴다. 채널 하나를 독립 데이터 반복으로 계산하지 않는다. 그래프의 입력 content hash와 이전 실험의 source provenance를 검증한다. 이전 결과 파일을 수정하지 않는다.

## 핵심 대조: 두 종류의 차원을 구분

R을 임의로 바꿀 수 있는 receipt 공간에서 합의 kernel 차원은

\[
\#\text{receipts}-\#\text{수신이 있는 행}
\]

이다. 실제 R은 R=TDMH로 제한된다. 수신 중심 행들이 원래 그래프의 양의 directed Laplacian을 포함하므로 실제 H 방향에서 rank는 채널당 N−k다. k는 연결성분 수다.

따라서 다음 두 결과를 함께 제시한다.

- **직접 숨는 송신별 성분:** R−Sᵀdiag(receipt_count)†Y의 제곱 크기와 전체 R 대비 비율.
- **실제 복원 가능성:** Y 전체에서 H의 연결성분 평균을 제외한 부분, q, R을 복원한 실제 오차.

앞의 비율만으로 실제 정보 손실을 판단하지 않는다. 연결성분 개수는 원래 전체 그래프에서 계산한다. 큰 citation 그래프의 일부 basis를 검사하고 전체 rank를 추정하지 않는다.

## E/J를 연결한 조건의 검사

조건별 forward 결과에 해당 E/J를 실제 포함한다. `sum`으로부터 복원한 상태에서 E와 J를 다시 계산하여 실제 값과 비교한다. 같은 Y만으로 추가 항이 결정됨을 확인하는 검사다.

모든 조건의 inverse는 Y만 사용한다. E/J를 loss로 추가해 역문제를 풀거나 조건별 decoder를 학습하지 않는다. 따라서 E/J 추가 조건이 더 잘 복원했다고 주장할 수 없다. 조건별 관측 차원, E/J의 실제 값, 재현 오차를 통해 어떤 비선형 특징이 연결됐는지 보여준다.

J_node=2J_shared+J_distinct이므로 세 J를 별개 독립 정보로 세지 않는다. J의 부호와 trace 정의를 유지하며, 임의의 PSD 제약이나 전체 에너지라는 이름을 추가하지 않는다.

## 수치 계산과 자원 사용

- 모든 원래 그래프와 로컬 topology를 한 번 준비하고 재사용한다.
- 독립 합성 그래프는 disjoint union으로 GPU에서 함께 처리한다.
- citation은 전체 그래프를 유지한 채 특징 채널의 정확한 chunking을 사용한다. 모든 채널을 처리한다.
- CPU worker와 graph/channel 계산 단위를 실제 throughput 및 메모리 측정으로 선택한다.
- 로컬 메시지는 sparse gather/scatter로 계산한다. 정확한 희소 A와 Aᵀ를 CSR로 cache하여 복원에 재사용하고 dense 관측 행렬이나 dense AᵀA를 만들지 않는다.
- 글로벌 normal equation은 연결성분 평균을 제거한 공간에서 CG로 푼다.
- 실제 관측의 상대 잔차 허용치는 1e−8, 최대 반복 수는 10×가장 큰 물리 그래프 노드 수다. normal-equation 잔차도 별도 기록한다. 미수렴을 성공한 복원으로 제출하지 않는다.
- 실제 CG 잔차와 H/q/R/E/J 오차를 함께 기록한다. 0인 분모의 상대 지표는 정의되지 않은 값으로 남긴다.
- 진행 상황을 같은 터미널과 로그에 출력한다. 오류가 나도 원격 세션이나 부모 셸을 종료하지 않는다.

## 완료 판정

전부 성공했다면 전체 201개, 두 C, 세 상태, 다섯 관측 조건, 연속 단계의 J를 포함한 범위를 completion에 기록한다. input hash, 원래 노드·엣지·채널 수, batch/chunk 사용과 실제 처리량을 함께 남긴다.

DEBUG는 이전 DEBUG의 21개 그래프를 사용한다. 별도 profile과 새 출력 디렉터리를 사용하며 full 완료나 실제 citation 성능으로 보고하지 않는다. full 실행은 서버에서 수행한다.

## 이 결과로 할 수 있는 주장

현재 shared-H·known-C 계약에서 수신 합의 직접 상쇄와 실제 복원 가능성이 어떻게 다른지 말할 수 있다. E/J가 Y의 비선형 함수로 결정되는지도 확인할 수 있다.

예측 개선, 학습된 C의 효과, 독립적인 source별 상태, 관측 일부가 빠진 모델, 학습된 비선형 압축의 정보 보존은 이 실험으로 검증하지 않는다. 예측 모델에 E/J를 사용하는 다음 단계에서는 그 실제 forward·loss·gradient·optimizer 경로와 성능을 별도로 비교해야 한다.
